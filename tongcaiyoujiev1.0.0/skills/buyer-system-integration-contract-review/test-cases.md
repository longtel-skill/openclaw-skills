# 测试用例：buyer-system-integration-contract-review

## 说明

- **技能名称**：甲方视角审核系统集成服务合同（含包工包料）（`buyer-system-integration-contract-review`）
- **测试目标**：验证技能能按甲方硬性标准审核系统集成类服务合同，输出分级问题清单，并交付带修订痕迹的 `.DOCX`
- **通过标准**：关键用例须同时满足「识别正确 + 严重度分级合理 + 修订方向符合硬性标准」

---

## TC-01 触发与立场

| 项 | 内容 |
|---|---|
| 用例编号 | TC-01 |
| 用例名称 | 甲方审核触发与买方立场 |
| 前置条件 | 用户提供系统集成/实施交付合同文本或附件 |
| 输入 | 「请从甲方视角审核这份系统集成服务合同」+ 合同全文 |
| 预期结果 | 以买方/甲方立场审核；不适用卖方视角；报告含结论摘要与问题清单 |
| 优先级 | P0 |

---

## TC-02 先票后款与分税率专票

| 项 | 内容 |
|---|---|
| 用例编号 | TC-02 |
| 用例名称 | 发票与先票后款硬性标准（硬件13%/服务6%） |
| 前置条件 | 合同约定「款到后开具发票」或仅约定普通发票/未约定税率，或硬件与服务混开税率 |
| 输入 | 含「买方付款后 15 日内开票」或一律按单一税率开票的系统集成（含包工包料）合同 |
| 预期结果 | 标为**阻断**或**须改**；修订方向为每一次付款前先开专票且先票后款；**硬件 13%**、**服务（集成实施等）6%**，价款分列 |
| 优先级 | P0 |

## TC-05 付款分档（M ≥ 10 万）与质保金

| 项 | 内容 |
|---|---|
| 用例编号 | TC-05 |
| 用例名称 | 大额合同四节点与质保金 |
| 前置条件 | 合同总价 80 万元 |

## TC-06 违约责任范围与封顶

| 项 | 内容 |
|---|---|
| 用例编号 | TC-06 |
| 用例名称 | 甲方违约范围过宽 / 违约金超封顶 |
| 前置条件 | 合同对甲方约定宽泛违约金，或违约金超过合同额 20%，或乙方迟延交付/不合格无对等后果 |
| 输入 | 含「甲方任何不配合均按日罚违约金」且乙方违约无后果，或违约金约定为合同额 30% 的条款 |
| 预期结果 | 标为**须改**；甲方违约仅保留「不配合致延期」「迟延付款」；乙方须覆盖迟延交付、不合格、整改仍不达标、直接损失；双方违约金 ≤ 合同额 20%（小于 20% 可保留） |
| 优先级 | P0 |

## TC-09 验收报告处理

| 项 | 内容 |
|---|---|
| 用例编号 | TC-09 |
| 用例名称 | 验收报告修订或生成 |
| 前置条件 | 情形 A：原合同已有验收报告附件；情形 B：原合同无验收报告 |
| 输入 | A：带模糊验收单的合同；B：无验收附件的集成合同 |

| 优先级 | P0 |

## 回归检查清单

执行完整审核场景时，确认输出同时覆盖：

- [ ] 结论摘要（是否建议签约 + 硬性标准符合情况，含硬件13%/服务6%）
- [ ] 合同定性、交付模式与付款档位；硬件与服务价款分项
- [ ] 联调/割接/回退、数据迁移（合同含相关内容时）
- [ ] 验收报告：原有修订/原有接受/新生成
- [ ] 按严重度分级的问题清单（引用条款位置/摘录）
- [ ] 谈判/修改方向
- [ ] 声明：不构成法律意见
- [ ] 最终 `.DOCX` 带修订痕迹
