# 甲方视角：软硬件买卖合同审核

## 角色与边界

- **立场**：站在**买方/甲方/采购方**一侧，目标为控制交付风险、质量与维保、付款与税务、知识产权与数据、违约与退出成本。
- **非律师意见**：输出为**商务与条款风险梳理**，不构成法律意见；涉诉策略、强监管行业（金融/医疗/关键基础设施等）应提示用户咨询执业律师。

## 适用与不适用

- **适用**：软件许可/订阅（SaaS）、定制开发、软硬件捆绑销售、设备采购、**安装部署/实施上线服务**、维保服务、框架+订单、招投标后合同。
- **单列关注**：若合同仅为**纯硬件**、**纯软件**或**纯安装部署服务**，跳过不适用模块，并在报告开头说明审核范围；混合合同时须**分拆货物价款与服务价款**及对应税率。

## 甲方硬性商务标准（对照审核与修订时必须执行）

以下标准为甲方底线；违反即标为**阻断签约**或**签约前须改**，修订合同时须改到符合标准。

### A. 发票与先票后款

- 甲方付款前，乙方须**先向甲方开具发票**（先票后款）；**每一次**付款节点均适用，不得约定“款到开票”或仅末笔先票。
- 发票类型一律为**增值税专用发票**；税率按标的分拆（价款表述须与“含税/不含税 + 对应税率专票”一致）：

| 价款组成 | 专票税率 | 典型范围 |
|---|---|---|
| **货物 / 软硬件买卖**（设备、介质、软件许可费等按货物或销售软件计价部分） | **13%** | 硬件、标准软件许可/销售价款 |
| **安装部署等服务**（安装、部署、实施、上线、迁移、联调、培训若单列服务费等） | **6%** | 安装部署服务费、实施服务费 |

- 混合合同须在价格清单/付款条款中**分列**「货物价款（13%）」与「安装部署服务价款（6%）」；不得笼统开一张税率不明或一律 13%/一律 6% 的票（除非合同无服务价款）。
- 若某笔付款同时覆盖货物与服务，须按分项金额分别开具对应税率专票，或一张票内分税率明细且与合同分项一致。
- 开票主体须与签约/收款主体一致。

### B. 付款节奏（按合同总金额，含税口径与合同约定一致时以合同总价为准）

| 合同金额 M | 付款要求 |
|---|---|
| **M &lt; 1 万元** | 可接受**一次性支付**；仍须**先票后款**。 |
| **1 万元 ≤ M &lt; 50 万元** | **发货前 50%，验收合格后 50%**；或拆分成**大于两次**的付款（不得仅一次付清，且首次付款不得早于对应交付义务启动且比例不得显著前倾以致失控）。 |
| **M ≥ 50 万元** | **至少拆分成三次付款**：**发货前 30%，初验 30%，终验 40%**。 |

- 任一档位下，**每次付款前乙方都必须先开具发票给甲方**（对应税率：货物 13% / 安装部署服务 6%）。
- 含安装部署时：付款节点名称应能区分**到货/发货**与**安装部署验收（或初验/终验）**，服务价款不得在部署未验收前全部付清（小额一次性除外）。
- 审核时：对照合同金额落入哪一档；支付比例、节点名称（发货/初验/终验/验收）与次数不符 → **须改**；未见先票后款 → **须改或阻断**。

### C. 违约责任对等

- 违约金、解除权、赔偿范围、通知与宽限期等，**甲乙双方须严格对等**（不得仅约束甲方迟延付款，而卖方迟延交付/质量违约无对等后果或明显畸轻）。
- 发现单边罚则、单方无限责任豁免、仅甲方违约可解除等 → **须改**，修订方向为对称设置。

### D. 维保

- 质保/维保期限**至少一年起**（自约定起算点：优先终验/验收合格之日；合同未约定起算点则建议补全）。
- 短于一年或未约定 → **须改**。

### E. 签章

- 合同签署：**公章或合同专用章均可**；不得仅要求法定代表人签字而不盖章（除非用户另有指示）。
- 审核时若强制“仅财务章/仅法人章”等不合理限制，标为建议优化或须改（视是否影响效力与履约）。

### F. 修订痕迹与交付形态

- **修订原合同时必须保留修改痕迹**（Word 修订模式/红黑字比对可识别增删改）。
- **最终交付物为 `.DOCX` 文件**（不是仅 Markdown）；同时可在对话中给出结论摘要与问题清单，但完整修订稿以 `.DOCX` 为准。

## 工作流（按顺序执行）

1. **定性与拆分**
   - 判断主合同类型（买卖 / 许可 / 服务 / 混合），列出附件优先级（技术规格、**安装部署 SOW**、SLA、验收标准、价格清单）。
   - 标注适用法律与争议解决地；若与甲方注册地/项目地不一致，标为谈判点。

2. **抽取结构化事实表**（内部用，可摘要进报告）
   - 标的：产品/版本/数量/站点或用户数/部署形态（云/本地/混合）；是否含**安装部署服务**及服务范围。
   - 价款：总价、货物价款与安装部署服务价款分项、是否落入付款分档、里程碑比例与节点、是否含税、发票类型（货物 **13%** 专票 / 服务 **6%** 专票）、币种与支付路径、是否先票后款（每笔）。
   - 关键日期：交付日、安装部署窗口、试运行期、验收截止、质保起算、维保续约窗口（维保是否 ≥ 1 年）。

3. **对照「甲方硬性商务标准」+ 下方清单逐项扫描**
   - 每条发现须**引用原文**（条款编号或小节标题 + 摘录）；无法定位时写“未见明确约定”，并建议补全条款。
   - 硬性标准不符合项优先写入「阻断 / 须签约前修改」。

4. **分级与输出**
   - 按严重度归类：**阻断签约** / **签约前须改** / **可接受但建议优化** / **对甲方有利可保留**。
   - 对高风险条款给出**谈判方向**（一至两句）。

5. **生成带修订痕迹的 `.DOCX`**
   - 在原合同文本基础上修改：付款分档、先票后款、货物 13%/服务 6% 专票分列、安装部署范围与验收、违约对等、维保≥1年、签章表述等。
   - **保留修改痕迹**（使用 Word 修订标记：删改为删除线/修订，新增为插入修订；或等效红线稿且可区分原文与改后）。
   - 将文件保存为 `.docx` 并告知用户路径；不要用无痕迹的“干净替换稿”作为唯一交付（除非用户明确要求另附清洁版）。

## 甲方核心审核清单

### 1. 主体、订单与冲突

- 签约主体与开票/收款主体是否一致；是否存在**卖方关联公司**履约或收款但未连带担责。
- 框架合同与订单的**冲突规则**（后者优先？订单是否可单方变更？）。
- 签章：公章或合同专用章是否被不当排除。

### 2. 标的、规格与变更

- 标的描述是否可客观核验（型号、版本、配置清单、性能指标）；**“以卖方说明为准”**类表述对甲方不利。
- **范围蔓延**：需求变更计价规则、变更单签署权、卖方单方升级/远程改配是否需甲方同意。

### 3. 交付、安装部署与验收（软硬件 + 服务重点）

- 交付物清单：硬件序列号规则、软件介质/许可文件/文档、培训是否包含。
- **安装部署服务**（合同含此项时必须审核，缺失则建议补全或单列附件）：
  - **范围**：安装环境前提（机房/云账号/网络/权限）、部署架构、实施地点/远程、工作日与人数、联调对象、数据迁移、上线切换、知识转移/培训是否包含。
  - **甲方依赖**：甲方须提供的场地、账号、接口、窗口期；因甲方原因延误是否免责及工期顺延规则（避免无限期占用）。
  - **交付物**：部署手册、配置清单、账号与权限交接、测试报告、上线确认单。
  - **验收**：安装部署完成标准须可核验（功能点/性能基线/联调通过条件）；须约定**安装部署验收**或与初验/终验的衔接；不合格返工次数、费用承担、逾期违约。
  - **分包**：安装部署是否允许分包；分包商资质与乙方连带责任。
- **验收标准**：是否量化、可测试；避免“合理满意”“商业上可接受”等单方标准。
- **初验/终验**节点与**不合格处理**（返修、替换、退款、违约金是否对称）；金额 ≥50 万时须能支撑「发货 / 初验 / 终验」三次付款节点；含安装部署时，发货不等于安装完成，付款节点应能区分到货与部署验收。
- **试运行**：最长时限、通过条件、未通过是否可终止与退款/减价。

### 4. 价款、发票与税务（并入硬性标准 A/B）

- 货物/软硬件价款是否 **13%** 增值税专用发票；**安装部署等服务价款**是否 **6%** 增值税专用发票；价税与分项是否清晰。
- 混合合同是否分列货物与服务金额及对应税率；有服务费却未约定 6% 专票或与货物混开税率 → **须改**。
- 是否严格**先票后款**且覆盖每一笔付款。
- 付款次数与比例是否符合金额分档（见上表）；安装部署服务费宜与**部署/上线验收**节点挂钩，避免服务未完成即付清。
- 外币、汇率、代扣代缴（如有跨境）是否约定清楚。
- **自动涨价/续约涨价**条款；索引公式是否封顶。

### 5. 软件许可与知识产权（买方关注点）

- 许可性质：**永久/订阅**；用户数、CPU/核、站点、地理范围、**外包/关联公司使用**是否覆盖甲方真实使用场景。
- **禁止/限制**：审计权是否过重、是否禁止反向工程（评估与互操作性需求时尤为敏感）。
- **定制成果归属**：工作成果、文档、接口规格、**甲方数据之上形成的模型或报表**归属与使用。
- **开源与第三方组件**：合规声明、责任分配、更新义务。

### 6. 数据、安全与合规

- 个人信息与重要数据处理：**分包、跨境、日志留存、删除/返还**；等保/密评若适用是否在附件中落地。
- 云订阅：**数据位置、可用性指标、备份与恢复、退出时数据导出格式与时限**。
- **安全事件通知**时限与配合义务；漏洞修补责任。

### 7. 质保、维保与支持（并入硬性标准 D）

- 维保/质保**≥ 1 年**；起算点是否明确（优先终验/验收合格）。
- 硬件备件与响应时效（到场/远程）；软件缺陷分级与修复时限；版本升级是否另收费；**EOL** 与迁移支持。

### 8. 保证与责任限制

- 卖方保证是否涵盖**权属、不侵权、符合规格**；免责声明是否过度宽泛。
- **责任上限**是否过低（例如“合同金额 12 个月费用”且排除间接损失）；是否与甲方业务损失不匹配。
- **间接损失、利润损失、数据丢失**是否被不当排除；依法不可免责部分应提示。

### 9. 违约、终止与退出（并入硬性标准 C）

- 迟延交付/重大缺陷与迟延付款等违约后果是否**严格对等**、可操作。
- 卖方违约时甲方**单方解除**权是否充分；是否存在仅约束甲方的单边条款。
- **便利终止**（甲方业务变化）若缺失，可标为谈判项。
- 终止后：**许可是否终止、数据导出、已付费未使用部分退款、过渡服务**。

### 10. 争议解决与执行

- 仲裁/诉讼地、语言、适用法律；**证据保全与源代码托管（escrow）**是否在重大项目中有必要提及。

### 11. 涉外与特殊监管（条件触发）

- 出口管制、制裁合规（EAR/SDN 等）**陈述与违约后果**。
- 政府采购/招投标：是否与中标文件**实质性背离**。

## 输出格式

### 1）对话内报告（可先输出）

```markdown
# 软硬件买卖合同审核报告（甲方视角）

## 一、结论摘要
- 是否建议签约：是/附条件/不建议
- 硬性标准符合情况：发票（货物13%/服务6%专票）/先票后款、付款分档、安装部署范围与验收、违约对等、维保≥1年、签章
- 前三大风险（各一句话）

## 二、合同定性
- 合同类型与适用法律/争议解决（是否含安装部署服务）
- 合同金额与适用付款档位；货物价款与服务价款分项及税率
- 审核范围说明（已覆盖/未提供的附件）

## 三、问题清单（按严重度）
### 阻断 / 须签约前修改
| 编号 | 主题 | 条款位置与摘录 | 风险说明 | 谈判/修改方向 |
### 建议优化
（同上表头，可简化列）

## 四、对甲方有利或已较完善的条款（简列）
- …

## 五、附件与条款补全建议
- 建议补充的附件：安装部署SOW、验收测试用例、SLA、安全附录、数据清单…

## 六、声明
本报告为条款风险与商务要点梳理，不构成法律意见。
```

### 2）最终交付（必须）

- 文件格式：**`.DOCX`**
- 内容：修订后的合同（或合同修订对照稿），**保留修改痕迹**
- 生成方式建议：用 Python (`python-docx`) 或本机 Word/COM 生成；修订痕迹优先使用 Word 修订（`w:del` / `w:ins`）或明确可见的红线标记，确保甲方能看见相对原合同改了什么
- 输出路径告知用户，文件名建议包含原合同名与 `甲方审核修订` 字样

## 严重度判定参考（快速标尺）

- **阻断**：标的不清、验收不可执行、责任上限与核心义务严重失衡、数据出境无合法路径、知识产权归属与甲方目标根本冲突；**无票付款或拒绝专票且无法税务落地**；**高额合同一次性或严重前倾付款且无验收节点**；**约定含安装部署但范围/验收空白以致无法履约核验**。
- **须改**：付款分档/比例/次数不符硬性标准；非先票后款；货物未按 13% 或服务未按 6% 专票分列；违约不对等；维保短于一年；单方变更权在卖方；缺失关键保证；安装部署服务费与验收节点严重脱节。
- **建议优化**：措辞模糊、程序性通知不合理、审计权过宽但可限额定时。

## 与用户交互

- 若合同**脱敏**（金额、当事方、商业秘密），在报告开头注明假设与保留意见；金额不明导致无法套用付款分档时，须追问合同总价或按条款假设分档并标注。
- 若用户给出**商业目标**（例如必须本地化部署、必须取得源码/可迁移），将清单权重向该目标倾斜，**不得削弱**本章「甲方硬性商务标准」。
- 用户仅问“某一条是否不利”时，可只输出该条的**立场分析 + 修改建议**；一旦用户要求改合同或完整审核，仍须交付带痕迹的 `.DOCX`。
